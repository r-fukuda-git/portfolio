### 1. 正常系を守る「ガード節（Early Return）」
Goで最も大切で、最も頻出するパターンです。
「もしダメだったら、すぐに帰る（return）」という考え方です。
これを使うと、**「メインの処理」をネスト（深掘り）させずに書けます。**

```go
func process(score int) {
    // 【パターン】異常や例外を先に弾く
    if score < 0 || score > 100 {
        fmt.Println("不正なスコアです")
        return // ここで終了
    }

    // ここからは「正しいデータ」である前提でメイン処理が書ける
    fmt.Println("スコアを登録しました:", score)
}
```

### 2. 「カンマ ok」イディオム（存在確認）
マップの要素確認や、型アサーションで使います。
Go特有の「2つ目の戻り値」をチェックするパターンです。

```go
// 【パターン】Mapに鍵があるか確認
if val, ok := myMap["key"]; ok {
    // 存在したときだけの処理
    fmt.Println("値を発見:", val)
}

// 【パターン】型が合っているか確認
if s, ok := i.(string); ok {
    fmt.Println("これは文字列です:", s)
}
```

### 3. 初期化付き if（スコープ限定）
`if` の中でだけ使う変数をその場で宣言するパターンです。
コードがスッキリし、変数の影響範囲を狭められます。

```go
// 【パターン】実行結果を変数に入れて、そのまま判定
if length := len(user.Name); length > 20 {
    fmt.Println("名前が長すぎます")
}
// ここで length はもう使えない（安全！）
```

### 4. 複数条件の switch への逃げ
`if` が3つ以上続いたり、複雑になりそうなら、Goでは潔く `switch` に切り替えます。
Goの `switch` は条件式を書けるので、複雑な `if` よりも読みやすくなります。

```go
// 【パターン】if-else が重なりそうなとき
switch {
case age < 18:
    fmt.Println("未成年")
case age >= 18 && age < 65:
    fmt.Println("成人")
default:
    fmt.Println("シニア")
}
```

### 書き出しで迷わないための「思考手順」

もし「ifから先が書けない」と思ったら、自分にこう問いかけてみてください。

1.  **「この処理が実行されるために、最低限必要な条件（前提）は何？」**
    * → それを `if !条件 { return }`（ガード節）で最初に書く。
2.  **「この値、そもそも存在してる？」**
    * → `if val, ok := ...; ok`（カンマok）で書く。
3.  **「条件が3つ以上ある？」**
    * → `if` を諦めて `switch` と打つ。
