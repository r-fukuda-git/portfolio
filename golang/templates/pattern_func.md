### 1. 【基本型】 処理して結果とエラーを返す
Goで最も多く書くパターンです。
**「成功したら値とnil」「失敗したらゼロ値とerror」**を返すのが鉄則です。

```go
// パターン： (入力) -> (結果, エラー)
func fetchUser(id int) (User, error) {
    user, err := db.Find(id)
    if err != nil {
        // 失敗パターン：空のUserとエラーを返す
        return User{}, err
    }
    // 成功パターン：データとnilを返す
    return user, nil
}
```

### 2. 【メソッド型】 構造体に「動き」をつける
特定の構造体（データ）に紐づいた関数です。
`func` の後に `(u User)` のような**レシーバー**を書くのが特徴です。

* **値レシーバー：** データを参照するだけ（読み取り専用）
* **ポインタレシーバー（*付き）：** データの中身を書き換える

```go
type User struct {
    Name string
}

// パターン：データを「使う」だけ（値レシーバー）
func (u User) Greet() string {
    return "こんにちは、" + u.Name + "さん"
}

// パターン：データを「更新する」（ポインタレシーバー）
func (u *User) UpdateName(newName string) {
    u.Name = newName
}
```

### 3. 【コンストラクタ型】 新しい構造体を作る
Goには他の言語のような`new`専用の構文がないため、`New〇〇` という名前の関数を作るのが慣習（パターン）です。

```go
// パターン：構造体を初期化して、その「場所（ポインタ）」を返す
func NewUser(name string) *User {
    return &User{
        Name: name,
    }
}
```

### 4. 【関数を引数に取る型】 処理を外から注入する
「後でこれを実行しておいて」と、関数そのものを渡すパターンです。
HTTPハンドラや、共通処理を作るときによく使います。

```go
// パターン：引数に func を入れる
func ExecuteLog(task func()) {
    fmt.Println("開始します...")
    task() // 渡された関数を実行
    fmt.Println("終了しました。")
}

// 呼び出し方
ExecuteLog(func() {
    fmt.Println("メインの処理中")
})
```

### 迷った時の「型」の決め方フローチャート

「どんな`func`を書けばいいか」迷ったら、この順番で考えてみてください。

1.  **「何かのデータ（構造体）を操作したい？」**
    * YES → **メソッド型**（`func (u *User) ...`）
2.  **「新しいデータを作って返したい？」**
    * YES → **コンストラクタ型**（`func New...`）
3.  **「失敗する可能性がある処理？」**
    * YES → **基本型（2つ目の戻り値を `error` にする）**
4.  **「とりあえず共通の処理をまとめたいだけ？」**
    * YES → **基本型（引数と戻り値を決めるだけ）**
