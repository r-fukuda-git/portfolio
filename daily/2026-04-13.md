学習メモ
- variables.tf の役割：入力変数の「宣言」
  - このファイルは、このTerraformプロジェクト（prd 環境）が外部から受け取る設定値を「宣言」する場所です。
  - 例えば、/Users/r-fukuda/portfolio/terraform/aws/enviroments/prd/variables.tf ファイルでは、「env という名前の文字列型の変数が必要ですよ」「ec2_instance_count という名前の数値型の変数が必要ですよ」といった定義をしています。
  - これにより、この prd 環境を構築するためにどのような設定値が必要なのかが、このファイルを見るだけで一目瞭然になります。

- main.tf の役割：リソースの「定義」と変数の「使用」
  - このファイルは、実際にどのようなAWSリソース（VPC, EC2インスタンスなど）を作成するかの「ロジック」を記述する場所です。
  - module "ec2" のようにモジュールを呼び出し、具体的なリソースの作成はモジュールに任せています。
  - モジュールに値を渡す際に ec2_instance_count = var.ec2_instance_count のように var. を付けて変数を参照します。
  - これは variables.tf で宣言された変数の「値」をここで使用するという意味です。

- モジュールを疎結合（お互いに依存しすぎない状態）にするため、リソースの情報を直接参照せず、入力（variable）と出力（output）を明確に定義して、上位階層で依存関係を制御するように設計しました

- 保守性を考えてモジュール構成にリファクタリング（作り直し）しました
- Terraformのモジュールは、**「カプセル化（独立したカプセル）」**という設計思想
  - 親が在庫（変数）を持っていても、子の部屋（モジュール）の中に「それを受け取るための棚（variable ブロック）」を設置しない限り、子は外にある変数にアクセスすることができません。
  - ステップ1: 子の variables.tf にも variable "env" {} と書く（受取口の設置）。
  - ステップ2: 親の main.tf の module "ec2" { ... } ブロック内で、env = var.env と書く（配線をつなぐ）。

- `iam`, `ec2`, `networking` 各モジュール間の依存関係を、`variable`（入り口）と `output`（出口）を使って接続。
- `Unsupported attribute` エラーを解決するための `outputs.tf` の定義・修正。

- 子モジュール内で作ったリソースは、`output` で明示的にエクスポートしない限り、親モジュールからは一切見えない（カプセル化）。
- 親で呼ぶ名前、子で出す名前、そしてリソース自体の属性（`.id` や `.name`）の3つが一致して初めて「配線」が通る。

- すべての `output` 定義を完了させ、`terraform plan` の正常終了を確認する。
- 成功後、リソースの命名規則が `project_name` や `env` を反映した意図通りになっているかプレビューを精査する。

Terraform AWSプロバイダーの認証評価順序（優先度順）
プロバイダブロックの静的設定（Static Credentials）

main.tf の provider "aws" ブロック内に直接ハードコードされた access_key や secret_key など。

※セキュリティ上の理由から非推奨ですが、存在する場合は最優先されます。

環境変数（Environment Variables）

ターミナルで設定された AWS_ACCESS_KEY_ID、AWS_SECRET_ACCESS_KEY、AWS_SESSION_TOKEN や AWS_PROFILE など。

※先ほどのトラブルでCLIとTerraformの挙動のズレを生みやすい部分です。

共有認証情報ファイル（Shared Credentials File）

デフォルトでは ~/.aws/credentials ファイルに保存されている永続的なアクセスキー。

共有設定ファイル（Shared Configuration File）

デフォルトでは ~/.aws/config ファイルに記述された設定。

AWS SSO（IAM Identity Center）のセッション情報、assume_role の設定、外部プロセス（credential_process）などの設定はここで評価されます。

コンテナのロール（Container Credentials）

AWS環境上で実行されている場合、Amazon ECSのタスクIAMロールや、Amazon EKSのIRSA（IAM Roles for Service Accounts）から取得する一時クレデンシャル。

EC2インスタンスプロファイル（Instance Profile Credentials）

EC2インスタンス上で実行されている場合、そのインスタンス（メタデータサービス）にアタッチされたIAMロールから自動的に取得する一時クレデンシャル。

- フォーマットの自動整形：terraform fmt
- 構文・バリデーションチェック：terraform validate
