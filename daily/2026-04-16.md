
# golang
- r.ParseForm() とは
  - Go言語のnet/httpパッケージにおいて、HTTPリクエストのボディ（POSTデータ）とURLクエリパラメータを解析し、r.Formフィールドにデータを格納するメソッドです。
  - 基本フォームの解析を実施し、その後、r.Formを用いてデータの取得を実施する
- interface{} は「どんな種類のものでも入れられる魔法の箱」を意味
  - インターフェースは「この箱に入るには、こういう機能（メソッド）を持っていないとダメ」という条件を書きます。しかし {}（中身が空っぽ）と書くことで、「何の条件もない＝何でも入る」という意味
  - Goのバージョン1.18以降では、この interface{} を短く書ける any というキーワードが追加されました。実務では var args []any と書くのが今の主流です。
- db.Exec の可変長引数が any を要求するため、動的に値を渡すにはスライスも any 型で宣言する必要がある
  - args... のようにドットを3つ書くと、配列の中身を展開して渡せます
  - 数がわからない、把握できないためドットを記載して箱から取り出せる
  - db.Exec という関数は、ある時はID（数字）を受け取りますが、別の機会ではタイトル（文字）やステータス（真偽値）も受け取ります。
  - db.Exec を作った人は「この関数にはどんな種類（型）のデータが来るかわからないから、とりあえず何でも入る魔法の箱（any）で渡してね」というルール
  - 全てはGoの型が厳しいため

# PrintfやSprintfのケースのまとめ
- %v (Value - デフォルト)
- %s (String - 文字列)
- %d (Decimal - 10進数)
- %t 論理値（bool）をtrueまたはfalseで出力する。
- %f 浮動小数点数（float）を固定精度で出力する。
- %q 文字列をダブルクォーテーションで囲んで出力する（"string"）。
- %x 16進数（小文字）で出力する。
- %T 値の型（type）を出力する。

# SQLについて
- SQLの文法の違い: データを追加する INSERT INTO の場合は、どのカラムに値を入れるか指定するために tasks (title, completed, ...) のようにカッコを使います。
- DELETEの正しい形: 一方、データを削除する DELETE FROM の場合は「行そのもの」を削除するため、テーブル名の直後に (id) のようにカラム名を指定する必要はありません。「どのテーブルから」「どの条件（WHERE）で」削除するかだけを指定します。
- 一括削除の考慮点
  - トランザクションの制約の考慮が必要
    - 3件選択して2件までしか削除できないケースなど全然ありうるため、全部実施するか、失敗するかの処理が必要
  - ループ処理で1個ずつDELETEは非効率
    - 1回のSQLでまとめて削除する工夫が必要になる

# 具体的にどうすればいいのか
- 「失敗した量」を増やす
  - 綺麗なコードを書こうとせず、あえてコンパイルエラーをたくさん出してください。Goのエラーメッセージは親切なので、エラーを読み解く回数が多いほど、言語の仕組みが脳に刻まれます。
- 「出力（アウトプット）の量」を増やす
  - 読むだけでなく、毎日1つでいいので「昨日までは書けなかった小さなプログラム」を保存（GitHubなどにアップ）してください。
- 「Bashの置き換え量」を増やす
  - ls -l 相当の機能、grep 相当の機能、curl で叩くAPI連携など、Bashでできることを片っ端からGoで書き換えてみてください。

# 関数の引数の順番
- 関数の定義では、引数の順番を (id int, title string, completed bool, duraion int) としています。
- Goは定義された順番通りに型をチェックするため、「int型の場所にstring型が入ってきた」と判定してコンパイルエラーを起こします。
