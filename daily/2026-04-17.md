# ハンドラーとDB処理の混同

- 現在の loginUser は、引数が (username string, password string) となっている「ただの関数（DB処理用）」です。
- しかし、その中で r.Method や r.FormValue といった「HTTPリクエスト（ハンドラー用）の変数」を使おうとしているため、コンパイルエラーになります。

## 具体例

- ハンドラー（受付・ウェイター）: お客さんから注文（HTTPリクエスト）を受け取り、料理（HTTPレスポンス）を運びます。
- DB処理（シェフ）: 注文票を見て、冷蔵庫（データベース）から食材を取り出し、料理（データ）を作ります。

# ハンドラーってなに？

- ハンドラーは「関数」の一部ですが、特別なルールを持った関数のこと

## ハンドラーと関数の違いは？

- 関数（Function）: 何か仕事をしてくれる「道具」全般のことです。どんな引数を受け取っても、何を返しても自由です（例: signupUser や AddTask）。
- ハンドラー（Handler）: Webサーバーの世界において、「絶対に (w http.ResponseWriter, r \*http.Request) の2つを受け取らなければならない」という厳しいルールを守っている関数のことです。このルールを守っている関数だけが、インターネットからの通信を受け取ることができます。

## HandleFunc と HandlerFunc の違い（1文字の違い）は？

- http.HandlerFunc（r がある＝型・資格）
  - 意味: 「w と r を受け取る」というルールの**受付係の資格（ライセンス）**そのものです。
  - 使い方: 今回の authMiddleware の引数や戻り値のように、「ここには資格を持った受付係が入ります よ」と指定するために使います。

- http.HandleFunc（r がない＝関数・命令）
  - 意味: 「このURL（ドア）に、この受付係を配置しろ！」という**店長からの命令（アクション）**です。
  - 使い方: main 関数の中で、http.HandleFunc("/add", myTasks.addHandler) のように、URLと担当者を結びつけるために使っています。

# 構造体ってどのように設計するのか?

- 下記の2つのような観点で設計を実施する
  - テーブルごとの構造体（データモデル層）
    - データベースのテーブルの1行分を、Go言語の世界に持ってくるための単なる「入れ物（段ボール箱）」です。
    - 基本的にはデータを入れるだけなので、データベースに接続するための道具（\*sql.DB）は持たせません。
  - 処理単位の構造体（リポジトリ・サービス層）
    - データモデル層を使って、実際にデータベースに書き込んだ理読み込んだりする
    - 作業に必要な道具（\*sql.DB などの外部接続）をすべて持ち、各種のメソッド（ハンドラーやDB操作）を実行します。

- データモデル層はさらに2つの役割を分けて設計することがある
  - Entity（エンティティ）:
    - データベースのテーブルと1対1で対応する「純粋なデータの箱」です。
    - 例: User テーブルから取得した ID, Username, PasswordHash をすべて持ちます。
    - テーブルのカラムと完全に1対1になるように作ります。
  - DTO（Data Transfer Object: データ転送オブジェクト）:
    - 画面やAPIにデータを渡すため「専用に作られた箱」です。
    - 例えば、フロントエンドにユーザー情報を返すとき、Entityの中にある PasswordHash は絶対に外に漏らしてはいけません。そこで、「パスワード抜きの安全な箱（例: UserResponse 構造体）」を新しく作り、必要なデータだけを移し替えてから送信します。
    - フロントエンド（Reactやスマホアプリ）が「この形だと使いやすい！」と要求する形に合わせて作ります。
```
// ① Entity（DBと会話するための生の箱）
type UserEntity struct {
    ID           int
    Username     string
    PasswordHash string // 絶対に外に出してはいけない
    CreatedAt    time.Time
}

// ② DTO（フロントエンドに渡すための安全・綺麗な箱）
type UserDTO struct {
    ID       int    `json:"id"`
    Username string `json:"username"`
    // PasswordHash はここには書かない（安全）
}
```

# Go言語の主語動詞の概念

- 構造体（Struct）＝ 名詞・主語（誰が / 何が）
- メソッド（Method）＝ 動詞（何をする）
