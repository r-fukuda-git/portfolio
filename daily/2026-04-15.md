# メモ
- ビルドって何？共有ストレージとは
  - docker compose up -d --build 再びるど
  - docker compose up --build
  - docker compose -f docker-compose.yml up
  - イメージ（Image）: ビルドによって作られた「お弁当パック」本体です。これにはプログラム本体、OSの最小機能、ライブラリ、実行コマンドなどが全て封印されています。一度作ると中身は変わりません。
  - Dockerfile: そのお弁当の「レシピ」です。
  - なぜ --build が必要だったか: Dockerは「レシピが変わっていないなら、前回作ったお弁当を使い回そう」と楽をしようとします（キャッシュ）。コードを書き換えた時は、明示的に「作り直して！」と指示しないと、古いお弁当が出されてしまうため、--build が必要だったのです。
  - volumes:
    - データの永続化	コンテナを捨てても、Mac側のフォルダにデータが残っていれば、新しいコンテナで続きから始められます（DBのデータなどに必須）。
    - リアルタイム同期	Mac側でファイルを書き換えると、コンテナ内にも即座に反映されます（ソースコードの共有など）。
    - 今回の例	./init フォルダを繋ぎましたね。Macの init/init.sql を書き換えると、Dockerの中からもそれが見える仕組みです。

- Webアプリケーションとしてブラウザからのリクエストを処理し、HTMLを表示するためには、現在の標準入力（CLI）ベースのコードをHTTPサーバーの仕組みへ書き換える必要
  - Web化するには、Go標準の net/http パッケージを使用して、リクエストを受け付けるようにします。
  - w (ResponseWriter): サーバーからブラウザへ送る「返事」を書くための道具です。
  - r (Request): ブラウザから届いた「お願い（URLや入力データ）」が入っている袋です。

- エラーハンドリング: strconv.Atoi などは、数字以外（あいうえお等）が入力されるとエラーを返します。
  - 実務では _ で捨てず、if err != nil で適切にユーザーへエラーを伝えるべきです。
- バリデーション: AddTask 内で title == "" のチェックを行っているのは非常に良い実装です。
  - Web版でも「空のタスクは作らせない」という意図を維持しましょう。
- 型変換の失敗を StatusBadRequest（400番台：ユーザー側のミス）、DB保存の失敗を InternalServerError（500番台：サーバー側の問題）
- :=（短縮変数宣言）と =（代入）の違いは、**「新しい変数を作るのか、それとも既存の変数に値を上書きするのか」
  - := （新しい箱を作る：宣言と代入）
  - = （既存の箱を使う：代入）
- Panicの回避: 今回 template.Must を使用しているため、テンプレートに不備があると即座にパニックが起きています。実務では Must を使わずに err を受け取り、適切に http.Error を返すことで、サーバー全体が止まる（パニックになる）のを防ぐ設計が好まれます。
- タスクが100万件あったらどうしますか？
  - 現在はGo側のループでカウントしていますが、データ量が増えた場合は DB の COUNT 文を使って、SQL側で集計した数値のみを取得するように改善します
- QueryRow の使用: 1行だけ結果が返ってくることがわかっている場合は、Query よりも QueryRow を使うのが一般的です。
- .Scan() による代入: SQLの結果を変数（totalCount など）に直接流し込みます。
- ネットワーク負荷の軽減: 10万件のタスクデータ（大きなスライス）をネットワーク経由でGoに送る必要がなくなり、「100000」という小さな数値だけが届くようになります。
- 計算処理のオフロード: 大量データを全件取得してGoで処理するのではなく、DB側で計算を完結させて結果のみを受け取ることでリソースを節約する実務的手法。
- ボトルネック
  - サーバー処理時間 (Latency): Goがリクエストを受けてから、HTMLを生成し終えるまでの時間。
  - DBクエリ実行時間: SQLの SELECT COUNT 自体にかかっている時間。
  - メモリ使用量 (Memory footprint): 10万件をGoに読み込む際（旧方式）と、数値だけ受け取る際（新方式）の消費メモリの差。
- http.NewServeMux(): マルチプレクサ（ルーター）の生成。
- mux.HandleFunc(パターン, 関数): 特定のパスに処理関数を紐付ける。
- r.URL.Query().Get("キー"): URLからクエリパラメータを取得するメソッド。
- 高階関数 (Higher-order function): 関数を引数として受け取り、関数を返す関数。latencyLogger がこれに当たります。
- クロージャ (Closure): http.HandlerFunc の中で、外側の変数（start など）を保持したまま実行できる無名関数。
- time.Now() と time.Since(): 時間の取得と経過時間の計算。
- db.QueryRowContext(...): 1行だけ結果が返ってくることを前提としたクエリ実行メソッド。
- .Scan(&count): ポインタ (&) を使用。DBから返ってきた結果を、Go側の変数 count のメモリアドレスに直接書き込みます。
- db.QueryContext(...): 複数行の結果が返ってくるクエリ実行メソッド。
- defer rows.Close(): 遅延実行 (defer)。この関数 (executeOldWay) を抜ける直前に必ず実行されます。エラーが起きても確実にDB接続（カーソル）を閉じるためのGo特有の安全装置です。
- for rows.Next() {}: DBからデータを取り出せる限りループし続ける処理。
- append(records, rec): **スライス（可変長配列）**の末尾にデータを追加する組み込み関数。
- runtime.GC(): ガベージコレクション（不要になったメモリの解放）の強制実行。
- runtime.ReadMemStats(&m): 現在のGoランタイムのメモリ統計情報を、変数 m に書き込む（ここでもポインタを利用）。
