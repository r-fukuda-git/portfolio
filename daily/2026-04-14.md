1.terraform.tfvars: 実際の値を入れる場所（例：backup_window = "18:00-19:00"）
2. variables.tf (Root): 【今足りないのはここ】 変数の存在を定義する場所
3. main.tf (Root): module "rds" に backup_window = var.backup_window と渡す場所
4. modules/rds/variables.tf: モジュールが値を受け取るための窓口

Terraformの dynamic ブロックは、**「同じ構造のブロックを、リストやマップの中身に合わせて自動で繰り返し生成する」**ための非常に便利な構文です。
dynamic "parameter" {           # ① 生成したいブロックの名前（今回は parameter ブロック）
  for_each = var.rds_parameters  # ② 繰り返しに使うデータ（MapやList）を指定
  content {                      # ③ 実際に生成される中身をここに書く
    name  = parameter.key        # ④ parameter.key は Mapの「左側（キー）」
    value = parameter.value      # ⑤ parameter.value は Mapの「右側（値）」
  }
}
dynamic "名前": ここに書いた名前のブロックが複数作られます。

for_each: ここに渡した Map ("key" = "value") の数だけループします。

parameter.key / value: dynamic で指定した名前（今回は parameter）が一時的な変数名になります。Mapを使っている場合、自動的に .key と .value という属性が使えます。


1. Dockerfile（単品の作り方）
役割：1つの「コンテナ（サーバー）」の中身をどう作るかを定義する

何をする？: OSの指定、ライブラリのインストール、ソースコードのコピー、実行コマンドの設定。

成果物: 「イメージ」（これを使えばどこでも同じサーバーが起動できるという金型）。

料理で例えると: 「絶品カレーの作り方」。

材料：肉、ルー、野菜

手順：野菜を切る、煮込む、ルーを入れる

今回のケース: 「GoのWebサーバー」という1つのマシンをどう作るか、が書かれています。

2. Docker Compose（全体の構成）
役割：複数の「コンテナ」をどう連携させて動かすかを定義する

何をする？: 「アプリ用コンテナ」と「DB用コンテナ」を繋ぐ。ネットワークの設定、ポート番号の割り当て、環境変数の管理。

成果物: 「システム全体」。

料理で例えると: 「ディナーコースの注文票」。

カレー（Dockerfileで作るもの）を出す。

それに合うサラダ（別のイメージ）を並べる。

飲み物（さらに別のイメージ）もセットにする。

今回のケース: 「Goアプリ」と「PostgreSQL」をガッチャンコして、1つのシステムとして動かす設定が書かれています。
